CPU 写入的一个数，如何让 LED 闪烁？

沿箭头从上往下读。每个框是一段处理过程；右侧解释它为什么存在。此实验已由使用者上板确认 LED 能闪烁。

同一片 FPGA 内部RISC-V 软核运行 C 程序；APB 外设由 Verilog 描述。

① C 程序：发出写请求

write_u32(1, APB0 + 0);

地址 = 0xF8100000，写入值 = 1

CPU 决定“写到哪、写什么”。

程序稍后写入 0，再写 1，如此循环。

↓

② SoC：按地址找到 APB0

地址译码器选择这个外设窗口

总线桥把 CPU 请求转换成 APB 操作

地址分配在硬件中已配置。

soc.h 的宏只是把这个地址告诉 C 程序，不会创建硬件。

↓

③ APB：把地址和数据送过去

本次访问：局部偏移 PADDR = 0

写入值的最低位 PWDATA[0] = 1

APB 是接口协议，不是存储器。

先准备，再进入访问阶段；双方完成握手后，外设接收这次写入。

↓

④ apb3_top：保存这个控制位

偏移为 0，且写握手完成时，在时钟沿：

_zz_sig <= apb_pwdata[0];

assign sig = _zz_sig;

_zz_sig 是 1 位寄存器。

保存最近写入的值，直到下次有效写入。

sig 是线，把保存值送往下一段。

↓

⑤ 顶层连线：把 sig 交给 LED 引脚

soc_gpio_OUT[1] = sig

soc_gpio_OE[1] = 1

OUT 决定输出高还是低。

OE=1 允许引脚输出，不等于灯亮。

此通道的控制者已从 SoC GPIO 改成 sig。

↓

⑥ 板上电路：LED 响应引脚电平

soc_gpio[1] → GPIOR_24 → LED

引脚电平随着 sig 的 0 / 1 变化

管脚配置：inout，3.3 V LVCMOS。

OE 已固定为 1，因此作为输出使用。

高电平亮还是低电平亮，取决于板上接法。

蓝色：软件与总线传输　绿色：自定义寄存器　浅橙色：引脚与 LED

为什么会闪烁？软件每约 100 ms 改写一次

0–100 mssig = 1引脚高电平
100–200 mssig = 0引脚低电平
200–300 mssig = 1引脚高电平
300–400 mssig = 0引脚低电平

调用 bsp_uDelay(100000) 阻塞约 100 ms；此时 CPU 忙等，寄存器仍保持输出。完整亮灭周期约 200 ms（5 Hz）。上图时间为相对时间，忽略少量执行开销。

需要复习时，再展开下面的说明

1. 软件到底写了什么？

write_u32(数据, 地址) 的第一个参数是数据，第二个是地址。APB0 等于 0xF8100000；EXAMPLE_APB3_SLV_REG0_OFFSET 等于 0。

while (1) {
    write_u32(1, APB0 + EXAMPLE_APB3_SLV_REG0_OFFSET);
    bsp_uDelay(100000);  // 100000 微秒 = 100 毫秒

    write_u32(0, APB0 + EXAMPLE_APB3_SLV_REG0_OFFSET);
    bsp_uDelay(100000);
}

这段程序写的是自定义 APB 外设。LED 的输出使能已在硬件中固定，因此这里不需要调用 SoC GPIO 初始化函数。bsp_uDelay() 使用 CLINT 计时器做忙等，延迟期间 CPU 不去执行其他应用逻辑。

2. APB 怎样完成一次写入？

APB 主端在 SoC 中，自定义模块 apb3_top 是从端。地址和数据由主端给出，PREADY 由从端返回。

阶段主端从端
准备PSEL=1，PENABLE=0；给出地址、数据，PWRITE=1等待访问阶段
访问PSEL=1，PENABLE=1；保持地址和数据PREADY=1 时，在该时钟上升沿完成传输
需要等待时维持访问阶段PREADY=0，暂不完成传输；本例固定 PREADY=1
 
factory_doWrite = PSEL && PENABLE && PREADY && PWRITE;
// 只有偏移为 0 且 factory_doWrite 成立，寄存器才接收数据。

每次 APB 传输处理一个地址处的一次读或写，没有 AXI 式突发传输。本例只使用写入数据的最低位。

3. sig、OUT、OE 分别负责什么？
名称含义
_zz_sig1 位寄存器，记住软件最近一次写入的 bit0。
sig内部信号线，连续传递寄存器的值。
soc_gpio_OUT[1]送给第 1 号 GPIO（从 0 编号）的输出数据，已改接 sig。
soc_gpio_OE[1]引脚输出缓冲器的开关。1：驱动高/低电平；0：停止驱动，呈高阻态。

FPGA 的输入、输出和输出使能最终汇合到同一个物理引脚。引脚名称仍叫 soc_gpio[1]，不代表它必须由 SoC 内置 GPIO 控制。

// 顶层实际代码：右侧从左到右对应 [3]、[2]、[1]、[0]
assign soc_gpio_OUT = {soc_gpio_out_cpu[3:2], sig,  soc_gpio_out_cpu[0]};
assign soc_gpio_OE  = {soc_gpio_oe_cpu[3:2],  1'b1, soc_gpio_oe_cpu[0]};

GPIO0、GPIO2、GPIO3 仍保持原来的控制方式。GPIO1 只由 sig 驱动，避免多个输出源争用。

5. 这次成功验证了什么？还有什么没有验证？

已观察到 LED 闪烁，说明本例“软件写偏移 0 的 bit0 → 自定义寄存器 → 引脚输出”的控制通路能够工作。它为以后配置加速器提供了最小示例。

当前 Interrupt.v 的读数据固定为 0，因此没有寄存器读回验证；它也没有使用 reset 输入给 _zz_sig 赋初值，图中的保存关系从第一次有效写入后开始。

源码核对还发现：顶层 apb_paddr、apb_pwdata、apb_prdata 缺少显式位宽声明。在允许隐式线网的 Verilog 设置下会成为 1 位线，导致多位数据或地址截断；本例只写偏移 0 的 bit0，不能覆盖这个问题。扩展多寄存器前，需要单独补齐位宽并验证。生成的 SoC 地址端口为 16 位、读写数据为 32 位，外设地址端口目前为 32 位，应明确做零扩展连接。
